# Updating content — and getting it onto the live site

`portfolio-store` (this repo) is the **single source of truth**. The website and the
chatbot both read from this one Neon database — they store nothing of their own.

```
                         ┌───────────────────────────────┐
   edit a seed file  ──►  │   Neon  (portfolio-store DB)  │
   run it with psql       └───────────────────────────────┘
                              │                        │
        reads 6 tables at     │                        │  reads knowledge_base
        BUILD time (ISR 1h)   ▼                        ▼  vectors at QUERY time (live)
                   ┌───────────────────┐      ┌──────────────────────┐
                   │  portfolio-website │      │     rag-chatbot      │
                   │   (Vercel)         │      │     (Render)         │
                   └───────────────────┘      └──────────────────────┘
```

Two things follow from this:

1. **The website is a static build.** It reads the DB when Vercel builds it, then
   serves HTML. A DB change is *not* live instantly — it shows up on the next
   rebuild, which happens automatically at most once an hour (ISR
   `revalidate = 3600` in `src/app/page.tsx`), or immediately if you redeploy.
2. **The website and the chatbot read different things.** The website reads the
   six structured tables. The chatbot reads `knowledge_base` (pre-computed
   embedding vectors). Editing `seeds/experience.sql` updates the website's
   Experience section but the chatbot won't *mention* the change until you also
   regenerate the embeddings (Section 4).

---

## 0. One-time setup

You need `psql` and the database URL.

```bash
brew install postgresql        # if you don't have psql

# Same database, two env-var names across the repos:
#   rag-chatbot/.env        NEON_DATABASE_URL=...
#   portfolio-website/.env.local   DATABASE_URL=...
export NEON_DATABASE_URL="postgres://user:pass@ep-xxxx.neon.tech/dbname?sslmode=require"
```

Use the **pooled** connection string from the Neon dashboard (host contains `-pooler`).

---

## 1. The common case — change text that shows on the website

Example: fix a bullet on the Uber role.

```bash
# 1. Edit the seed file
$EDITOR seeds/experience.sql

# 2. Apply it — every seed file is an upsert (ON CONFLICT DO UPDATE), safe to re-run
psql "$NEON_DATABASE_URL" -f seeds/experience.sql

# 3. Verify the DB has the new value
psql "$NEON_DATABASE_URL" -c "SELECT company, role, bullets FROM experience ORDER BY display_order;"

# 4. Commit the seed change — this file is the source of truth, not the DB row
git add seeds/experience.sql && git commit -m "content: reword Uber Kafka bullet"
```

That's it for the database. Now get it onto the site — pick one:

| Want | Do |
|---|---|
| It's not urgent | Nothing. The next hourly ISR revalidation picks it up (≤ 60 min). |
| Now | Redeploy the website: Vercel dashboard → `portfolio-website` → Deployments → ⋯ → **Redeploy**, or `git commit --allow-empty -m "redeploy" && git push` on the website repo, or `vercel --prod` from the website dir. |

> The chatbot does **not** need a redeploy for content changes — it reads the DB
> live. It only needs the embedding step in Section 4.

### Which seed file feeds which part of the site

| Seed file | Website section | Notes |
|---|---|---|
| `seeds/personal_info.sql` | Hero, About, Contact, page `<title>` | Key/value. See Section 3. |
| `seeds/experience.sql` | Experience | `UNIQUE (company, role, start_date)` is the upsert key. |
| `seeds/projects.sql` | Projects (homepage) | **Only rows with `is_featured = TRUE`** are shown, ordered by `display_order`. `UNIQUE (title)`. |
| `seeds/skills.sql` | Stack / Skills | `UNIQUE (name)`. |
| `seeds/education.sql` | Education | `UNIQUE (institution, degree, start_date)`. |
| `seeds/achievements.sql` | Education → achievements | `UNIQUE (title, organization)`. |
| `seeds/knowledge_base.sql` | *(none — chatbot only)* | Generated by `scripts/embed.py`. See Section 4. |

## 2. Add a new row (new job, new project, new skill…)

Append an `INSERT ... ON CONFLICT` block to the matching seed file, then re-run it.

**New featured project** — must set both `is_featured` and `display_order` or it
won't appear on the homepage:

```sql
-- in seeds/projects.sql
INSERT INTO projects (title, category, description, bullets, tech_stack,
                      github_url, live_url, is_featured, display_order)
VALUES (
  'Distributed Rate Limiter',
  'personal',
  'Token-bucket limiter with a Redis backend and a Go client SDK.',
  '["Sliding-window + token-bucket hybrid", "p99 < 2ms at 50k rps"]'::jsonb,
  ARRAY['Go', 'Redis', 'gRPC'],
  'https://github.com/AG-AGENT47/ratelimiter',
  NULL,
  TRUE,
  3
)
ON CONFLICT (title) DO UPDATE SET
  category = EXCLUDED.category,
  description = EXCLUDED.description,
  bullets = EXCLUDED.bullets,
  tech_stack = EXCLUDED.tech_stack,
  github_url = EXCLUDED.github_url,
  live_url = EXCLUDED.live_url,
  is_featured = EXCLUDED.is_featured,
  display_order = EXCLUDED.display_order,
  updated_at = NOW();
```

```bash
psql "$NEON_DATABASE_URL" -f seeds/projects.sql
git add seeds/projects.sql && git commit -m "content: add rate-limiter project"
```

Then deploy per Section 1, and run Section 4 so the chatbot knows about it.

Notes on the JSON/array columns:
- `bullets` is **JSONB** — write a JSON array string and cast: `'["a","b"]'::jsonb`.
- `tech_stack` (projects) and `courses` (education) are **`TEXT[]`** — use
  `ARRAY['Go','Redis']`.
- `start_date` / `end_date` are real `DATE`s (`'2026-05-11'`). For an ongoing
  role use `end_date = NULL, is_current = TRUE`. For a role that hasn't started,
  `end_date = NULL, is_current = FALSE` — the website detects `start_date` in the
  future and shows a "Starting <month>" label with an "upcoming" badge.

## 3. Add a brand-new hero / about field

`personal_info` is a key/value table, so a new field is just a new row:

```sql
-- in seeds/personal_info.sql, inside the existing INSERT ... VALUES list
('now_playing', 'chess (badly)'),
```

```bash
psql "$NEON_DATABASE_URL" -f seeds/personal_info.sql
```

**But** the website only renders keys it explicitly reads. Adding a *value* for an
existing key (`bio`, `hero_lede`, `hero_pills`, `about_p2`, `now_reading`,
`portrait_caption`, …) works with no code change. Adding a *new key name* also
needs a one-line change in the website repo:

- add the key to the `PersonalInfo` type in `portfolio-website/src/lib/types.ts`
- render it in the relevant component (e.g. `src/components/sections/Hero.tsx`)

Formatting conventions already supported in `personal_info` values:
- `E'line one\nline two'` — the `\n` becomes a line break (`richText.tsx`).
- `*wrapped in asterisks*` — renders emphasised.
- `hero_pills` is `|`-separated; the last pill gets the accent treatment.

## 4. Make the chatbot aware of the change

The chatbot answers from `knowledge_base` — 46 text chunks, each with a 768-dim
Gemini embedding vector, pre-computed and committed as `seeds/knowledge_base.sql`.
When you change resume-type content, regenerate it:

```bash
# The chunk text lives in scripts/embed.py (the CHUNKS list). If your change is
# new information (not just a typo fix), edit/append a chunk there first.
$EDITOR scripts/embed.py

export GEMINI_API_KEY="AIza..."        # free, no card: https://aistudio.google.com/apikey
pip install -r scripts/requirements.txt
python scripts/embed.py                # rewrites seeds/knowledge_base.sql (~5s, 46 chunks)

psql "$NEON_DATABASE_URL" -f seeds/knowledge_base.sql   # TRUNCATEs + re-inserts every row

git add scripts/embed.py seeds/knowledge_base.sql
git commit -m "kb: refresh embeddings for rate-limiter project"
```

No redeploy needed — the chatbot reads the new rows on the next question.

Rules:
- `EMBED_MODEL` / `EMBED_DIMS` in `embed.py` **must** match what `rag-chatbot`
  uses (`gemini-embedding-001`, 768). Don't change one without the other and a
  migration — a dimension mismatch makes every retrieval error out.
- Purely cosmetic website copy (a pill label, a caption) doesn't need this step.

## 5. Delete a row

Seed files never delete — re-running them won't remove anything. Do it explicitly:

```bash
psql "$NEON_DATABASE_URL" -c "DELETE FROM projects WHERE title = 'Old Project';"
```

Then also remove that row's `INSERT` block from the seed file (so a fresh
environment rebuild doesn't bring it back), remove its chunk from
`scripts/embed.py`, and run Section 4.

To just hide a project from the homepage without deleting it, set
`is_featured = FALSE` in `seeds/projects.sql` and re-run the seed.

## 6. Schema changes (new table / new column)

Content edits never need this — only a genuinely new *shape* does.

```bash
# 1. New migration file, next number, DDL only (CREATE TABLE / ALTER TABLE)
$EDITOR migrations/006_certifications.sql

# 2. New seed file with ON CONFLICT upserts
$EDITOR seeds/certifications.sql

# 3. Apply
psql "$NEON_DATABASE_URL" -f migrations/006_certifications.sql
psql "$NEON_DATABASE_URL" -f seeds/certifications.sql

# 4. Website: add a query in src/lib/db.ts + a type + a component to show it.
#    Chatbot: add chunks in scripts/embed.py, run Section 4. No chatbot code
#    change — retrieval is table-agnostic.
```

Migrations are append-only and run in filename order. Never edit an applied one;
write a new one that alters.

## 7. Verify (run any time)

```bash
# Row counts
psql "$NEON_DATABASE_URL" -c "
SELECT 'personal_info'  AS t, COUNT(*) FROM personal_info
UNION ALL SELECT 'skills',        COUNT(*) FROM skills
UNION ALL SELECT 'experience',    COUNT(*) FROM experience
UNION ALL SELECT 'education',     COUNT(*) FROM education
UNION ALL SELECT 'projects',      COUNT(*) FROM projects
UNION ALL SELECT 'projects_featured', COUNT(*) FROM projects WHERE is_featured
UNION ALL SELECT 'achievements',  COUNT(*) FROM achievements
UNION ALL SELECT 'knowledge_base',COUNT(*) FROM knowledge_base;
"

# Knowledge base is 768-dim and fully populated
psql "$NEON_DATABASE_URL" -c "
SELECT count(*), vector_dims(embedding) FROM knowledge_base GROUP BY 2;
"   # expect: 46 | 768

# What the website's projects query will actually return
psql "$NEON_DATABASE_URL" -c "
SELECT display_order, title FROM projects WHERE is_featured = TRUE ORDER BY display_order;
"
```
